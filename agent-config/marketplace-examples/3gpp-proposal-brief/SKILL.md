# 3GPP 提案对比与会前简报

作者：durunfeng（杜润峰）。把用户选定的提案整理成可用于会前讨论的中文简报。重点是原文中的具体主张、适用条件与分歧，不是逐段复述全文。

## 选择材料

- 用户提供了文件或工作区路径时，以这些材料为准。需要提取 DOCX/PDF 时，使用当前可用的文档工具或转换 Skill；记录实际返回路径。
- 用户明确说“演示”“使用内置示例”时，用 Skill 资源读取工具读取本包 [references/demo-proposals.md](references/demo-proposals.md)。使用激活结果给出的 Skill 名称或资源标识，不猜测磁盘目录。示例为虚构材料，标题和结论均保留“演示材料，非真实 3GPP 文稿”标记。
- 用户尚未给出材料，也没有要求演示时，询问要比较的文件、TDoc 或会议主题。只在用户要求查找最新文稿时开展在线检索，并核对官方会议清单。不要把简报任务扩展成整个会议的下载或研究。

## 比较方法

从材料中提取 TDoc/示例编号、标题、来源、会议与议程（若材料包含）。编号或会议信息缺失时如实说明。

围绕实际分歧选择比较维度，例如报告触发条件、信息内容、网络与终端职责、兼容方式、信令与隐私代价。每个结论关联具体文稿和章节、页码或段落；内置示例使用 [DEMO-A §A1] 这类定位。

区分“明确提出”“有条件支持”“明确反对”“未讨论”和“资料不足”。一家公司提出方案 A，不等于反对方案 B；共同署名也不证明所有技术选项都获得一致支持。没有明确反对原文时不要填写“反对”。

分别描述提案主张、分析者推断和已确认的会议决定。只有会议记录或已通过文本支持时，才写“会议已采纳”。不同版本、不同会议的主张分别列出，不把旧稿与修订稿当作两个独立支持者。图片无法辨认时说明缺口，不补造技术细节。

## 交付

按用户要求调整篇幅，通常包含：

1. **会前结论**：主要分歧、可能的共同点，以及尚未确认的事项。
2. **提案对比表**：技术维度 × 提案/来源，每格给出主张、条件与来源定位；没有证据的格子保留缺口。
3. **讨论问题**：围绕尚未解决的条件、代价和验证方法提出可在会上讨论的问题，不预设答案。
4. **参考资料与范围**：逐项列出实际使用的文稿、版本和来源，说明未读取或无法确认的部分。

默认直接在对话中交付简报。用户要求文件时保存 Markdown 并返回实际路径；知识库发布由用户另行指定。内置示例不访问网络、不扫描工作区，也不将演示结论写成真实标准结论。

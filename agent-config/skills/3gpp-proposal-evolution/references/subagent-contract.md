# 单链委派

父 Agent 的 task 包含：链 ID、前后会议和日期、KI/WI/Release/TR、全部当前修订稿、上次候选稿、每条关系的类型/等级/原文位置、需要比较的章节、准确源文件和提取文件路径、资料缺失、独立输出路径。没有父 Agent 的聊天历史也应能完成任务。

传入“我方观点”原文及用户材料的位置。内部观点只用于获准的工作区分析，不拼入网络搜索词或上传到外部服务。没有提供时传空，不能以公司历史提案补位。观点材料冲突时并列说明，不自行选择。不要在最终结果中暴露无关内部资料。

子 Agent 只执行这条链，不运行父级关系扫描、再委派、发布或向用户重复追问；所需信息缺失时返回具体缺口。继承的父 Skill 调度说明不适用于子任务。用工具核对原文并只写分配的结果文件，返回完成/部分完成/失败、结果准确路径和简短摘要。无法写文件时在返回值中保留已完成分析，不能伪造文件路径。

结果必须包含三个分析章节，另附简短的提案编号、会议、比较范围、关系类型、证据等级和资料限制：

## 1. 总结提案要点

解决的问题、核心主张、实体/接口/流程/部署假设、相对前稿新增/删除/修改、术语和章节变化、Editor’s Notes 及本次处理结果。无前稿时只总结本稿，不能伪造差异。重要事实注明 TDoc、章节或正文块。

## 2. 我方可能会关注的

将用户关注点对应到具体机制，说明可能影响和需要确认的问题。分析性影响用“可能”，不是事实或行动承诺。没有观点时注明：“当前任务没有提供我方观点，以下仅列出可能需要关注的技术点，不代表我方立场。”

## 3. 与我方观点的差异

| 比较项 | 我方观点及来源 | 提案观点及 TDoc/位置 | 判断 | 可能影响/待确认 |
|---|---|---|---|---|

判断只用“一致、部分一致、存在差异、未涉及、无法判断”。双侧都要有依据；没有我方观点时写“缺少我方观点依据，无法判断”，不输出臆测立场。未提及不是反对，替代方案不必然冲突。联合署名不证明每个成员支持所有条款。

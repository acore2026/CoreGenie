# 按章节拆分 DOCX

确认原始 DOCX 的准确路径和拆分级别（1、2 或 3）。上传文件使用工具提供的完整工作区路径，不移动原件；同名文件不唯一时先询问。没有指定级别时询问用户。

使用包内 [scripts/split_docx.py](scripts/split_docx.py)，不要现场重写拆分算法。Bash 的 `cwd` 使用激活结果给出的 `skillRoot`；每次调用的 shell 变量独立。

```bash
python3 scripts/split_docx.py --input /workspace/uploads/<upload-id>/document.docx --level 3
```

默认在原件旁创建 `<原文件名>-split-<唯一编号>/`。也可传 `--output /workspace/<新目录>`，目录必须不存在。重复运行创建新目录；用户明确要求替换时先保留旧结果，再处理指定目录。

## 拆分规则

- 目标级别及上级标题开始新的输出单元；更深标题留在所属单元中。
- 父章节在子标题之前的正文单独保留，包括导言、段落、表格和图片。文档开头的前言也保留。
- 子文档开头补充原样复制的上级标题。实际切分按标题层级与位置，章节编号仅用于命名；支持附录和自动编号标题。自动编号保留在文档属性中，但文件名不计算其显示值，未提取到编号时使用 0，前置序号保证文件名唯一。
- 复制原 DOCX 包并替换正文切片，保留关系、样式、编号、图片、嵌入对象、页眉页脚、脚注和批注。不会执行宏或嵌入内容。

## 检查与交付

读取 `split-summary.json`，检查 `status`、正文块覆盖数、各输出文件及警告。脚本检查每个源正文块恰好分配一次（补充的父标题另计），并验证包内关系；检查失败时不声称拆分完成，保留已有结果和具体错误。

说明生成文件数、结果目录和警告；有条件时用文档阅读器抽查含表格、图片的章节。不能仅凭文件数量承诺视觉格式完全一致。

使用时请注意：输出保留原包的辅助部件，可能包含当前章节未用到的媒体、批注或脚注，文件可能较大；这项操作不适合用于删除敏感内容。页码、目录、跨章节引用和自动编号在独立文档中可能需要更新。无可识别标题时停止，不按文字长度猜章节，也不自动改变拆分级别。

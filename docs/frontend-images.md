# 前端轻量镜像

按钮、文案、布局等仅影响前端的改动，可以运行 `Publish frontend-only CoreGenie image`，选择当前后端的完整发行版本，例如 `1.15.5`。

流程仍然发布 Docker 镜像：构建前端，复用固定 digest 的主应用镜像，只追加前端层。新版本为 `1.15.5-ui.<提交前8位>`，不会覆盖 `latest` 或原有发行标签，也不更新沙箱 broker/runner。保留基础镜像中的旧哈希资源，有助于已经打开的页面加载旧资源。

运行：

```bash
gh workflow run build-and-push-image-frontend.yaml -R acore2026/CoreGenie --ref master -f base_version=1.15.5
```

工作流会从基础镜像读取后端源代码提交，检查到当前提交的所有差异。涉及服务端、数据库、collector、Agent 配置、沙箱或主应用依赖时拒绝发布，改走完整镜像构建。该检查不能代替前端与现有 API 的兼容性验证。

部署前确认运行中的后端与所选基础版本一致，不能把已升级的后端降回旧版。优先使用工作流摘要里的 digest 引用，继续使用 `deploy-existing-container.cjs` 更新主应用，保留端口、挂载、代理和认证设置。脚本拒绝打断运行中的任务，并在新容器启动失败时恢复旧容器。

目标服务器直接从 GHCR 拉取；已有层可以复用。不要在两端传输完整镜像 tar。回退使用部署脚本保留的旧容器或上一镜像。切换应用容器仍有短暂中断，前端轻量镜像不代表零停机。

完整发行版本继续使用原有构建和发布流程。耗时以工作流实测为准；第一次安装前端依赖和首次下载基础层仍需要时间。

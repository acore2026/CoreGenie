2026-10-08 调整。启动脚本使用下列默认值；显式配置的较小预算仍然生效。

当前工作台已启用不限总运行时间、工具调用和模型调用次数的配置；以上预算只在启用对应限制时使用。单次工具的执行时间、文件大小和沙箱资源仍有上限。

内存和 CPU 配置是每个 runner 的上限，不是预留资源。12 个任务同时达到内存上限会超过本机物理内存，因此没有取消所有资源限制。输出仍保留 1 MiB 截断，避免把大量日志塞入模型上下文。模型上下文、图片大小、上游 API 配额和归档解压大小限制不能仅凭服务器空闲内存取消。

沙箱通过新 socket 接管新请求，旧 broker 等已有调用结束后退出。服务端配置需要在没有运行中任务时部署新版本。执行超时或线程创建失败时，broker 清理对应容器并释放容量；大脚本写入 stdin 也计入超时。

启动配置：`AGENT_MAX_CONCURRENCY=12`、`AGENT_RUN_CONCURRENCY=8`、`SANDBOX_MAX_CONCURRENCY=12`、`SANDBOX_RUNNER_MEMORY=4g`。生产部署需要同时更新容器环境变量；镜像默认值不会覆盖现有容器环境变量。

## Markdown 转换故障

同日检查发现子 Agent 的运行编号采用 `call_...`，旧 broker 只允许 UUID，导致 Bash、Python 和单文件转换全部报 `invocationId must be a UUID`。这与脚本、输入 DOCX 和资源余量无关，等待重试不能解决。

客户端现在为非 UUID 调用生成沙箱编号；broker 同时兼容旧客户端的有界运行编号，并映射为安全的容器标签。这样现有运行中的 Agent 也能直接恢复。已通过相同 `call_...` 编号的 Bash/Python 调用和两份真实 DOCX 的 `convert-batch` 转换测试。
